# 2026-03-17 工作日志

## 今日目标

继续收敛 Deep Research 主链路，减少历史兼容包袱，提升流式稳定性、编排器可维护性，以及新闻/投融资搜索的新鲜度和可追溯性，为多 agent 投研报告能力打一个更干净的基线。

## 已完成事项

### 1. Deep-only 主路径收口

- 前端 `useChat` 去掉 chat/deep 双轨分支，收敛为只服务 orchestrator / deep research 的单一路径。
- 前端 API 抽象删除普通 chat 相关死代码，避免继续围着失效接口做兼容。
- 后端删除废弃的 `chat` API 和对应测试，主链路统一为 Deep Research。
- 后端全局异常处理不再把完整 traceback 直接返回给客户端，减少敏感内部细节泄露风险。

### 2. Deep Research SSE 稳定性改造

- 在 `quantum-chat-backend/api/deep_research.py` 中引入 `_SSEEventEmitter`。
- 连续 token / subagent_token 事件会先聚合再发送，避免长报告时事件过碎、前端卡顿。
- 事件队列改为有上限的 `asyncio.Queue`，降低长文本输出时的内存堆积风险。
- 在 `step`、`agent_start`、`error` 等非 token 事件发送前会先刷新累计 token，保证顺序更稳定。
- 补充回归测试，覆盖 token 合并、关键事件前刷新、不同 agent 隔离三个场景。

### 3. Orchestrator Prompt 模块化

- 将 `quantum-chat-backend/dagent/orchestrator.py` 里的超长 `ORCHESTRATOR_SYSTEM_PROMPT` 拆成按职责划分的静态片段：
  - 头部定位
  - 全局硬约束
  - 模式选择
  - 模式 0/1/2 规则
  - 子 Agent 能力说明
  - 收尾持久化动作
- 新增 `_compose_prompt_sections()`，统一组装静态 prompt；`_build_system_prompt()` 只负责追加当天系统时间。
- 模式 1 的编排要求改成显式“严格遵循已加载的 `investment-research` skill”，减少报告结构规则继续堆进 orchestrator prompt 的倾向。
- `_load_skill_files()` 的注释补充了边界说明，明确 orchestrator 只加载自身依赖的 skill，降低编排层与子 Agent 私有规则混杂的维护风险。

### 4. Skill 缓存语义收敛

### 5. 新闻/投融资搜索新鲜度与并行度优化

- 扩展 `quantum-chat-backend/dagent/tools/news_tools.py` 里的 `search_web(...)`：

  - 支持 `search_depth`
  - 对“精确日期过滤”优先于 `days`
  - 兼容较老版本 Tavily client 的参数回退
- 新增 `recent_date_window(days_back=90)`，给 agent 一个稳定的“近期检索时间窗”工具，减少模型自己乱写年份或直接扫 365 天。
- 新增 `search_web_batch(...)`，基于线程池并发跑多条 Tavily 查询，用于双语检索、多角度融资扫描、逐公司补漏验证，避免低效串行调用。
- 明确“数据截止日期”语义：
  - 指本次检索/核验完成日期
  - 通常应与生成日期一致
  - 不应再拿“最新事件日期”或“正文中最晚一条新闻日期”充当截止日期
- 更新 `quantum-chat-backend/dagent/subagents/news_agent.py` 的系统提示：

  - 双语或多角度搜索优先 `search_web_batch`
  - 近期融资排序优先按时间，而不是默认按金额

## 当前判断

- 当前最大收益已经从“删死代码”转到“提高结果质量和规则表达质量”。
- 这轮用户暴露的问题，本质上不是单一搜索词写得差，而是四层东西同时偏了：
  - tool 默认时间窗过宽，导致 Tavily 很容易把旧融资混进来
  - agent/skill 对“最近”和“截止日期”语义约束不够硬
  - 并行搜索能力缺位，导致多角度验证时容易为了省调用而只打一条宽泛 query
  - 赛道全景分析容易只停留在头部公司，早期团队和新进入者信号没有被稳定纳入标准工作流
- 现在这四层已经开始对齐：
  - tools 提供精确日期和 batch 能力
  - 响应层对头部元信息做程序化兜底
  - subagent 提供近期问题与机会发现的固定动作
  - skill 提供更短、更清晰、对其他 AI 也更友好的操作规范
