# 通用规则

这个文件记录跨项目可迁移的通用 Harness 经验。

## 上下文管理

1. 不要一开始加载所有文档。
2. 先读地图和索引，再读细节。
3. 只在需要时打开 skill 的参考资料。
4. 让上下文回答“现在该做什么”，不要回答“这个世界上所有相关知识”。

## 架构约束

1. 模式边界必须显式。
2. 新能力应有明确落点：计划、执行、验证、产物。
3. 运行期状态和长期知识要分层，不要混存。
4. 新事件和新接口优先结构化。

## 熵管理

1. 新错误类型先记录，再抽象成规则。
2. 过时规则要删，不要只堆追加。
3. 一个规则只能有一个主事实来源。
4. 长文档一旦承担多个问题，就拆分。

## 产物原则

1. 有价值的复杂任务应留下可复用产物。
2. 产物要可追溯、可定位、可复查。
3. 不要把聊天记录当作最终知识资产。
