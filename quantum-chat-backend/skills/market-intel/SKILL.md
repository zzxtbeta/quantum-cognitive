# market-intel

## 何时使用

- 最近 / 最新融资
- 某公司近期进展
- 赛道融资全景
- 政策 / 规划 / 标准
- 市场规模 / 竞争格局
- 早期标的发现

## 核心原则

- 内部数据库与实时 Web 是同等地位的数据源，默认交叉验证。
- `数据截止日期` 指本次检索与验证完成日期，通常应与生成时间同日；不要拿事件日期、预测日期或未来月份充当截止日期。
- “最近 / 近期 / 最新”类问题先保证时间新鲜度，不要默认整年窗口。
- 需要同时做中文 / 英文 / 多角度搜索时，优先用批量并发搜索，而不是串行单条慢慢查。
- 没有可追溯来源的内容不能写成关键事实。
- 赛道全景、商业化、玩家地图类问题，不能只报头部公司；必须额外扫描近12个月新进入者、早期公司和首次曝光团队。
- 关键表格里的主条目优先只保留带可点击 URL 的事实；无 URL 的内容只能降级到“待核实/弱信号”。

## 最小工作流

### 1. 最近 / 最新融资

1. 先调用 `recent_date_window(days_back=90)`
2. 用 `semantic_search_news(query="[主题或公司] 融资")` 查内部库
3. 用 `search_web_batch(...)` 做中文 / 英文并发实时验证
4. 只保留窗口内、带来源链接的融资事件

### 2. 过去12个月融资全景

1. 明确 `start_date` / `end_date`
2. `semantic_search_news(query="[主题] 融资 投资 轮次 金额", top_k=20)`
3. `search_web_batch(["中文查询", "英文查询"], topic="finance", start_date=..., end_date=...)`
4. 对命中的重点公司逐个补漏
5. 同一公司多轮融资逐轮列出

### 3. 政策 / 规划

1. `semantic_search_news(query="[主题] 政策 规划")`
2. `search_web(..., topic="general", start_date=..., end_date=...)` 或较长 `time_range`
3. 优先保留政府、监管、标准组织等高可信来源

### 4. 早期标的发现

- 围绕“天使轮 / 种子轮 / pre-A / 初创 / spin-off / 科学家创业”几个信号搜
- 优先输出有时间、团队背景、技术方向、来源链接的候选
- 若本次未发现可靠早期标的，也要明确写出“本次未发现”

### 5. 赛道公司地图 / 商业化问题

1. 先拆价值链，不要把所有公司混成一张名单
2. 头部玩家和近12个月新进入者分开呈现
3. 对“成立 / 孵化 / spin-off / 首次融资 / 首次媒体曝光”做补充搜索
4. 内部 DB 缺失时，必须用 Web 补发现，不得因为 DB 没命中就留白

## 工具约定

- `semantic_search_news`：默认主检索工具
- `query_news_db`：仅用户明确指定来源时使用
- `recent_date_window`：给“最近 / 近期 / 最新”类问题生成精确日期窗口
- `search_web`：单条实时搜索
- `search_web_batch`：多条 Tavily 查询并发执行，优先用于双语和补漏

## 输出要求

- 最近融资优先按时间倒序，不要默认按金额排序
- 每条事件尽量包含：公司、金额、轮次、投资方、事件时间、来源
- 日期不完整时明确标注为年月或年份，不要伪装成完整日期
- 若声明 `数据截止日期`，其值应是本次检索完成日期
- 若正文涉及事件时间范围，单独写“事件时间范围”，不要混进截止日期
- 赛道全景问题必须单列“新进入者 / 早期信号”小节；没有结果也要显式说明
- 不写“我来帮你调研 / 我将并行调用”等过程话术，直接输出市场情报结论

## 禁止事项

- 禁止把 2023/2024 的旧融资混入“最近融资”而不注明窗口
- 禁止把预测年份、路线图年份、未来月份写成数据截止日期
- 禁止编造 URL
- 禁止只输出头部玩家名单就结束
- 禁止主动使用文件系统工具检索业务数据
