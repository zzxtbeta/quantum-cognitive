# 安全约束

## 目标

系统应避免：

- 泄露密钥或敏感配置
- 无约束地调用危险工具
- 将无来源内容伪装成可靠研究
- 把临时噪音错误沉淀成长期知识

## 密钥与配置

- `.env` 中的值视为敏感信息
- 不把密钥写进文档、测试或前端展示
- 日志和异常信息不要暴露敏感值

## 工具安全

- 每个新工具都要说明它能读什么、写什么、连什么
- 高影响动作应当可审计
- 覆盖写入或删除类动作要有明确保护策略

## 数据边界

- 前端数据、后端运行数据、长期知识要分层看待
- thread memory 不是长期知识库
- 临时搜索结果不能直接视为知识沉淀

## 输出安全

- 不编造 URL
- 不输出无来源评分
- 不把无来源判断包装成已验证事实

## 当前优先项

1. 保证敏感配置不会进入渲染面和日志面。
2. 给高影响持久化动作补保护策略。
3. 保持 deep 输出的来源忠实度。
