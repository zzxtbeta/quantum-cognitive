# 当前计划

## 当前目标

先把基础环境、控制面文档、目录边界和 Harness 治理机制搭好，再去细化编排与模型能力。

## Phase 1：控制面稳定化

目标：

- 仓库入口清晰
- 目录边界清晰
- 上下文加载路径清晰

交付物：

- 根级 `AGENTS.md`
- 前后端 `AGENTS.override.md`
- `docs/` 控制面文档
- `harness/` 运行资料目录

## Phase 2：Harness 防腐化机制

目标：

- 新规则有固定落点
- 新错误有记录和反哺机制
- 过时规则能被清理

交付物：

- `docs/ENTROPY_MANAGEMENT.md`
- `harness/rules/COMMON_RULES.md`
- `harness/rules/ERROR_PATTERNS.md`

## Phase 3：深度工作流显式化

目标：

- deep 模式不再只是会流式输出的聊天框

交付物：

- 规划态
- 验证态
- 产物态
- 对应的前后端事件契约

## Phase 4：行为级验证

目标：

- 不只验证 API 通不通，还要验证 Agent 有没有走对路

交付物：

- 路由评估
- 引用合规评估
- 产物完整性评估
- deep 事件合约测试

## 当前优先事项

1. 继续保持文档和规则的分层清晰。
2. 任何新错误类型先记入错误账本，再沉淀成约束。
3. 不让说明文档与运行资料重新混杂。
