# 可靠性要求

## 目标

复杂任务下，系统即使不能走到理想路径，也要保持：

- 状态可见
- 失败可解释
- 过程可恢复
- 结果可回看

## 可靠性要求

### 事件合约稳定

- 流式事件结构应尽量稳定
- 新事件类型必须显式接入
- 前端在事件缺失时要能安全降级

### 失败要暴露在正确层级

- API 错误暴露在路由层
- 工具错误记录进 tool logs
- 编排错误能在 deep 工作流里被看见
- 产物写入失败要有明确状态

### 每条关键路径要有回退

至少定义：

- 超时怎么办
- 空结果怎么办
- 部分结果怎么办
- 是继续、重试，还是停止

### 重要结果要持久化

- deep 研究不能只活在当前页面里
- 研究产物应显式保存，而不是依赖聊天记录推断
- 日志应支持事后复盘

## 当前优先项

1. 明确 deep 事件合约。
2. 把规划、验证、产物状态做成显式状态面。
3. 增加行为级测试，不只测 API 形状。
4. 明确知识写入成功和失败状态。
